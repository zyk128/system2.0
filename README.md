# 外卖健康星级评估（最终项目）

## 项目句子
我们为【想控制油脂和热量、常点外卖的人】，输入【一个外卖菜名】，系统匹配到数据里的菜品，根据【菜名 + 营养标签】输出【Nutri-Score 健康星级 1–5（A~E）】和建议，以便【下单前避开高油高盐高热量】。

## 两个例子
- 例子 A（普通）：输入「宫保鸡丁」或「Mapo Tofu」→ 输出该菜的热量、脂肪、钠、Nutri-Score 星级（如「1 星 / E：高油高热量，尽量少点」）。
- 例子 B（困难/拒绝）：输入数据集里没有的菜 → 输出「查不到，请人工判断」（数据集覆盖约 5000 道菜）。

## 健康星级怎么来（Nutri-Score，主星级）
- 星级 = 欧盟官方营养标签系统 Nutri-Score（A~E），A 最健康、E 最不健康，A→5 星 ~ E→1 星；**绝对标准**，不会「矮子里拔高个」。
- 扣分（0~40）：热量（能量 kJ）、糖、饱和脂肪、钠；加分：纤维、蛋白（蔬果/坚果按 0，偏保守）。得分映射 A(≤-1)/B(0~2)/C(3~10)/D(11~18)/E(≥19)。
- 数据缺口诚实处理：中式成分表无「糖」列 → 中式用**去糖简化版**（与美式不横向比）；无每份重量 → **按每份近似**；川/粤缺饱和脂肪 → 用单位版数据拟合中位比例估算（≈总脂肪×0.132，已标注）。
- 防泄漏：模型特征只用**菜名 + 来源 + 胆固醇**（都不在公式里），排除标签列（热量/糖/饱和脂肪/钠/纤维/蛋白）与泄漏列（总脂肪/总碳水）。
- 相对星级（脂肪+热量分位）仍保留为参考列 `health_star`。
- 网页支持填「个人信息（性别/年龄/身高/体重/活动量）」→ 用 Mifflin-St Jeor + 活动系数实时算个人每日所需能量（TDEE），热量占比按个人 TDEE 显示；未填或无效则回退 2000 大卡参考。

- 许可或使用许可：① CC BY 4.0；② CC BY 4.0；③ Kaggle 页面许可（教师批准）；④ CC BY 4.0（教师批准）

- 关键字段：`food_name, food_name_cn, calories, fat, protein, carbohydrate, fiber, source, category, health_star`（相对参考）、`nutri_star, nutri_grade`（Nutri-Score 主星级）、`servings`（份数）、`weight_g`（克重，仅单位版有真实值，其余来源 NaN）；单位版另含 `sodium_mg, sat_fat_g, carbon_g, water_l, land_m2`（其余来源为 NaN）。网页「分量（克）」显示：单位版用真实克重（整盘 ÷ 份数），其余来源无真实克重用统一参照值 250 克，并显示每份对应大卡
- 川菜/粤菜数据：`source` 按具体菜系标「川菜」或「粤菜」（与八大菜系 `source=中餐` 区分来源）；英文菜名入库（真实原样），中文译名仅展示用（人工对照，不影响营养数据）；与八大菜系完全同名的 27 道（如麻婆豆腐/宫保鸡丁/回锅肉）只保留八大菜系那份（去重）
- 单位版数据：`source` 标「中餐单位版」；英文菜名入库（真实原样），中文名为「中餐 320 道准确译名优先 + 其余机译」（仅展示用，不影响营养数据）；与现有菜名同名的 17 道去重；钠/饱和脂肪/碳足迹仅单位版菜有值
- 数据检查命令：`python data_process.py`（输出行数/星级分布/划分）；`python -m pytest tests/ -q`（数据契约测试，9 passed）
- 不能提交 GitHub 的内容：`data/raw/` 原始 xlsx/CSV
- 已知限制：钠/饱和脂肪/碳足迹只有单位版菜有值，其余来源没有，所以星级仍只看脂肪与热量；每份「份量」口径中餐与快餐不同；无蔬果含量字段；川/粤与单位版菜名为英文（网页有中文译名，单位版为机译仅供参考）
- 允许的最小结论：星级只反映「相对油脂与热量」的健康程度，不代表完整健康评价；数据集外的菜系统无法判断

# 最小真实数据项目 starter（模板说明）

starter 不含问题数据，也不替你选择任务。上面已按课程要求写清项目句子、两个例子和数据契约。

## 第一次运行

```powershell
python main.py
```

`main.py` 会依次运行：数据合并清洗 → 多数类基线 → 梯度提升候选 → 交互演示。也可分步运行：

```powershell
python data_process.py     # 数据预处理，输出到 data/processed/
python baseline.py         # 多数类基线，保存 metrics_baseline.json
python train_model.py      # 梯度提升候选，保存 model.pkl 与 metrics_candidate.json
python rough_model.py      # 数据集外菜名的粗估模型（查不到的菜用），保存 rough_model.pkl
python demo.py             # 控制台交互：输入菜名查询
python build_web.py        # 生成本地网页版 index.html（无服务器，浏览器双击打开）
python -m pytest tests/ -q # 数据契约测试
```

## 如何新增菜品（入口）

**省事入口（推荐）**：运行 `python add_dish.py`，按提示输入菜名、来源、热量、脂肪、蛋白、碳水、纤维（配料可选），脚本校验后写入 `data/raw/user_added.csv`，再重跑：

```powershell
python data_process.py   # 重新合并、算星级、划分
python build_web.py      # 重新生成网页
```

想让模型也学到新菜，再跑 `python baseline.py`、`python train_model.py`、`python rough_model.py`。

也可以手动在原始数据（中餐在 `data/raw/` 的八大菜系 xlsx 的 `Recipe` 表，快餐在 `data/raw/fastfood.csv`）按表头加一行。

**底线**：新增菜的营养数值必须是**真实来源**（菜单营养表、官方营养库等），不要编——编数据会破坏本项目「真实数据」承诺。新菜会自动按「脂肪 + 热量」分位数得到星级，并出现在网页的全部菜品列表里。
